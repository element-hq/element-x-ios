# Tests

Coverage target: **80%** (includes SDK, Compound, Rich Text Editor).

Tests use **Swift Testing**. XCUI targets (UITests, AccessibilityTests, IntegrationTests) stay XCTest.
- `@Test` display name = sentence, says what test check, e.g. `@Test("The token is forgotten once the last account is removed") func removeLastAccount()`.
- Function name = short title, scenario only — action/state under test (e.g. `initialState`, `removeLastAccount`, `unlockFailure`). Not `removeLastAccountForgetsToken`.
- Outcome lives in display name + asserts, never function name.
- Touch test file? Update existing tests to match: add missing display names **and** rename functions to scenario form.
- File order: test cases first, helpers below (Newspaper order).

One scenario = one test. New test? Check suite first. Scenario already tested? Add asserts to that test, update display name — no second test same setup, different checks. Different scenario → new test.

Assert start state before action, not just end — else test may pass without anything changing.

Test worth it? No tests for code excluded from coverage (`codecov.yml`). No asserts on what's already guaranteed (e.g. state machine transition).

Tests live in suite named for type they test.

## Shape

Building subject under test (X), simplest first:
- Inline init — few tests, no helper.
- `makeX(…)` — build X, return it. Caller pass all deps in. No need for suite state.
- `setupX(…)` — `mutating`, build X + its mocks, store on suite. Tests read `viewModel`/`context`/mocks from suite. Always name subject (`setupViewModel`, `setupService`), never bare `setup`/`setUp`.

`makeX` tests need more than helper return — mocks it built, suite state it touched? Change to `setupX`, store on suite. No tuple returns.

Suite use `setupX` or `makeX`, not both. Has `setupX`, tempted add `makeX`? Instead:
- `setupX` param.
- Mock `Configuration` param.
- Static mock on type extension (e.g. `RoomMemberProxyMock.mockAdmin`, `UserSettings.mock()`). Test-only fixture? `private extension` at bottom of test file fine.

Mock or fixture needed by 2+ tests? Share it (options above). One test only? Can stay inline.

Suite properties = only what tests touch: subject under test, mocks asserted on or reconfigured mid-test. Dependency only passed to init? Build inline in `setupX`, no property.

One test build subject by hand, rest via helper? Use helper, add parameter.

Suite = `struct`. Need lifecycle (`deinit`)? `final class`.

Shared state (static override, disk, keychain, real `UserDefaults`)? Prefer volatile/mock (`AppSettings.volatile()`, `UserSettings.mock()`) — no cleanup needed. Can't avoid? `final class` with both:
- `init` → reset to known state. Earlier test may have crashed, leaked.
- `isolated deinit` → restore. Keep later tests clean.

Given/When/Then comments (`// Given…`, `// When…`, `// Then…`) — helpful pattern for humans reading longer tests.

## Test Types

| Type | Location | Purpose |
|------|----------|---------|
| Unit Tests | `UnitTests/Sources/` | VM logic, state machines, services |
| UI Tests | `UITests/Sources/` | Flow coordinator integration |
| Preview Tests | `PreviewTests/Sources/` | Auto-generated snapshots from previews |
| Accessibility Tests | `AccessibilityTests/Sources/` | Auto-generated Xcode Accessibility Audits |

No `.serialized` suite traits needed — tests not run in parallel.

UnitTests + PreviewTests: `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor` — no redundant `@MainActor`. Touch file? Remove it.

## Flow Coordinators

Prefer UI tests over unit tests.
- UI test tap through flow, trigger screen actions. Unit test can't.
- Test flow only — what present, push, pop, dismiss. No screen state asserts — unit + preview tests cover that.
- No screenshot needed if preview snapshot already cover screen. Moving away from flow snapshots.

## Running

### Xcode Tools

Scheme + simulator not linked. Switch scheme → switch simulator too. Snapshot schemes need CI device, wrong device → snapshot mismatch:
- UITests → iPhone 17 (`iPhone-<os>`) or iPad A16 (`iPad-<os>`).
- PreviewTests → iPhone SE (3rd generation), sometimes named `📸 Snapshots`.

Note device before switch to snapshot scheme. Back to other scheme → restore it.

### Xcode MCP Missing

User declined add? CLI:
- Unit tests: `swift run tools ci unit-tests`
- CI help: `swift run tools ci --help`

## Mocks

Generated by Sourcery (configs in `Tools/Sourcery/`). Files in `Generated/` directories.
- Un-configured methods crash on purpose.
- Convenience `init` with `Configuration` + sane defaults, in `ElementX/Sources/Mocks/<Name>Mock.swift`:
  ```swift
  let mock = ClientProxyMock(.init(userID: "@alice:example.com"))
  ```
- Always create via `Configuration`. No bare `Mock()` then set properties by hand.
- Need different value? Add `Configuration` field with default. Mock has no `Configuration`? Add one.
- Manual config only for unusual or involved setup (e.g. closure confirming call, publisher driven mid-test).

## Async Testing

```swift
let deferred = deferFulfillment(context.observe(\.viewState.counter)) { $0 == 1 }
context.send(viewAction: .incrementCounter)
try await deferred.fulfill()
#expect(context.viewState.counter == 1)
```

Same pattern for publishers.

- Value expected → `deferFulfillment`. Nothing expected → `deferFailure`. Call expected → `waitForConfirmation`.
- Never `Task.sleep` or `Task.yield()` to wait — flaky on CI. Wait on durable state.
- Matching non-equatable enum? Test-only `@retroactive Equatable` (`$0 == .presentRoom(…)`) or `isX` var via `switch` (`$0.isCancel`). No `if case … true else false` closures — bloat when formatted.
- Every wait needs timeout. Helpers take `timeout:` on purpose. Hand-rolled wait (bare `for await`, continuation, stream loop) no timeout → failure hang full 60s default. Use helper.

## Previews & Snapshots

- Previews for **all main states**.
- Use `PreviewProvider` (not `#Preview`) — snapshot/accessibility tests generated from it.
- Add `TestablePreview` conformance → snapshot + accessibility tests generated.
- Snapshots stored in `<Target>/Sources/__Snapshots__/`, tracked via **Git LFS** (`git lfs install`).
- Re-record on correct device/OS if UI changes.
- Powered by [`pointfreeco/swift-snapshot-testing`](https://github.com/pointfreeco/swift-snapshot-testing). Failures produce 3 images: reference, failure, diff.
